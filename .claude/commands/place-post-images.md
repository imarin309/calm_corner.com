R2にアップロード済みの画像を、MDX記事の各セクションに配置してください。
工程写真の `<BuildStepGroup>` だけでなく、パッケージ・素組み・完成の `<ImageGallery>` も対象です。

## 対象ファイル

`$ARGUMENTS` で対象MDXファイルを受け取る。引数には画像の置き場所（ディレクトリ）も含めてよい。
対象ファイルが分からない場合はパスを聞く。

## 前提

- 画像は Cloudflare R2 の `https://assets.calm-corner.com/posts/{slug}/{ファイル名}` に既にアップロードされている
- `{slug}` は対象MDXファイル名（拡張子を除いたもの）と一致する

## 画像一覧の入手

引数で指定されたディレクトリ（サブディレクトリも含む）の `.webp` を一覧する。
ディレクトリの指定がなければユーザーに聞く。

## 配置先の区分

記事の並び順に、おおむね次の置き場所がある。記事によって無いものもあるので、実際の見出し構成を読んで確認する。

| 区分       | 写真の内容                                                         | 置き場所                                                            |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------------------------------- |
| パッケージ | 箱・ランナー                                                       | 冒頭の `<ImageGallery>`                                             |
| 素組み     | 塗装前の組み立て済み。正面・背面、ギミック、色分けが物足りない箇所 | 「組んでみた感想」などの `<ImageGallery>`（意図別に複数に分かれる） |
| 制作方針   | 設計書・カラーリング案のメモ                                       | 方針セクションの `<ImageGallery>`                                   |
| 工程       | 手元・塗料皿・パーツ単体                                           | `<BuildStepGroup>` の各 `<BuildStep>`                               |
| 完成       | 塗装後の組み上がり。撮影ブースでの作品撮り                         | 完成セクションの `<ImageGallery>`                                   |

## 手順

1. 対象MDXファイルを読み込み、slug（ファイル名）を確認する
2. 指定ディレクトリから画像一覧を取得する
3. MDX内で既に `src` に設定済みの画像をファイル名で照合し、まだ配置されていない画像を特定する
4. 見出し構成を洗い出し、`<ImageGallery>` と `<BuildStepGroup>` の位置、`src` が空のスロット数、既存の `<BuildStep>` の構成（number・title・images）を確認する
   ```bash
   grep -n "^##\|ImageGallery\|BuildStepGroup" content/posts/{slug}.mdx
   ```
5. **未配置画像を Read で目視する。ファイル名からの推測だけでグルーピングしない。**
   ファイル名と中身はしばしば食い違う（`head1-arm` が実際は腕だけ、`shadow` がハイライトではなくシャドウ、など）。
   20枚を超える場合は分割して読み、都度メモを取る。
6. 目視した内容をもとに、上の区分へ振り分ける
   - 素組みと完成はどちらも組み上がった状態なので、塗装の有無で見分ける。成形色そのままなら素組み
   - 素組みは手持ち・作業机の上、完成は撮影ブースや背景紙の上、という違いも手がかりになる
   - 空のスロット数と枚数が合わない場合は、ギャラリーの追加や削除を提案する。勝手に増やさない
7. 全画像の公開URLにHTTPステータスを問い合わせ、200が返ることを確認する
   ```bash
   curl -s -o /dev/null -w "%{http_code}" "https://assets.calm-corner.com/posts/{slug}/{ファイル名}"
   ```
8. `AskUserQuestion` で配置方針を確認する。各選択肢には `preview` で「置き場所・入る画像」の一覧を付け、見比べられるようにする
   - 工程写真の組み方（既存ステップの枠内に振り分け／「何を判断・工夫したか」ごとのステップに再構成／工程順にフラットに並べる）
     - 部位ごとのサブステップにはしない。中身が同じ話の繰り返しになり、本文のないステップができるため。塗り方や技法が部位で違うときだけサブステップを使う
     - 部位違いで同じ作業の写真は、1つのステップにまとめて caption に部位名を入れる（「胴体：オレンジと黒で塗り分ける」）
   - 素組みギャラリーの分け方。既存の意図別グルーピングを引き継ぐか、まとめるか
   - 同じギャラリーに複数枚入る場合は並び順
9. 決まった方針に沿って編集する。共通の注意:
   - 各画像は `{ src: "https://assets.calm-corner.com/posts/{slug}/{ファイル名}", alt: "", caption: "..." }` の形式
   - `caption` は下の「caption の書き方」に従って全区分で埋める
   - `alt` は空のままにする。`/blog-generate-alt` の担当
   - ファイル名の綴り違い（`comprete` など）は直さず、R2にある実名をそのまま参照する
10. 編集後、画像一覧の全ファイルがMDX内で参照されているかをファイル名の突合で検証する

## caption の書き方

文言を考える前に、既存記事の caption を読んで語調を揃える。

```bash
grep -rhoP 'caption:\s*"\K[^"]+' content/posts/*.mdx | sort | uniq -c | sort -rn
```

このブログの caption はおおむね次の傾向がある。

- 短い。多くは3〜15文字程度。「背面」「素組み」「青く塗る」「渋いパッケージ」
- 工程写真は、その写真でやっていることを言い切る。「下地を塗る」「髪の色を作る」「白の比率を多くした色で重ねる」
- 素組み・完成写真は、向きや装備、または一言の感想。「正面」「チョパムアーマー背面」「かっこいい！」「キリッ」
- 口語や顔文字が混ざる。「違和感ぱない」「実はこのポーズはimarinの定番。バリエーション増やしたい( ・∇・)」
- キットへの評価を1文で添えることもある。「ヘッドパーツが二つあるのはgoodだが、前髪のパーツは一つだけなのは残念」
- 同じ工程が何度も出る記事では、同じ文言を使い回している。無理に言い換えない

感想系の caption は書き手の主観なので、写真から自信を持って言えない場合は事実だけ書き、一言を足すかはユーザーに任せる。

## 区分ごとの注意

### 素組み・完成・パッケージの `<ImageGallery>`

- 向きや装備が読み取れる場合は caption に入れる。「正面」「背面」「チョパムアーマー装着」
- 前後の本文が特定の箇所に言及している場合（バーニアが白い、V字マークが色分けされていない、など）、その説明に対応する写真を同じギャラリーに入れる
- 意図の違うギャラリーを1つにまとめない。既存記事の分け方を尊重する

### 工程の `<BuildStepGroup>`

- `number` は連番で振り直す。小数はサブステップとして描画される
- 画像2枚以上で2カラム、1枚なら中央寄せ1カラムになるので、枚数の偏りを考えて振り分ける
- `title` は目視した内容から付ける。既存タイトルが中身と合わない場合は差し替える
- 各 `<BuildStep>` の本文（`xxx` などのプレースホルダー）はここでは変更しない

## 出力

- 区分ごとに、どの画像をどこへ置いたかの一覧を表示する。工程写真は番号・タイトル・画像枚数も添える
- 既存タイトルを差し替えた場合は、どう変えたか・なぜ変えたかを伝える
- 目視しても区分が判別できなかった画像があれば、名指しで挙げる
- ギャラリーのスロット数と枚数が合わなかった箇所を伝える
- alt と工程の本文が未記入であることを伝え、caption は仮置きなので手直し前提だと添えて、必要なら `/blog-generate-alt` や `/collab-writing` の利用を案内する
