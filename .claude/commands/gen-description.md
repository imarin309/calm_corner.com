ブログ記事のdescription（メタディスクリプション）、タイトルのキャッチコピー、記事本文の「この記事の要約」テーブルを生成してください。

## 対象ファイル

`$ARGUMENTS` で指定されたMDXファイルを読み込んでください。
引数が空の場合は、対象のファイルパスを聞いてください。

## 手順

1. 対象のMDXファイルを読み込む
2. フロントマターと本文の内容を把握する
3. 以下のルールに従ってdescription・キャッチコピー・この記事の要約テーブルをそれぞれ生成する
4. 生成した内容をユーザーに提示し、承認されたらフロントマターおよび本文を更新する

## descriptionの生成ルール

- **100〜120文字**（日本語）にする
- 記事の要点・結論を含め、検索ユーザーが「この記事を読めば知りたいことがわかる」と感じる内容にする
- 記事で扱っている製品名・キーワードを自然に含める
- 煽りすぎず、記事の内容に忠実な表現にする
- 文末は「〜を紹介します。」「〜を解説します。」「〜をまとめました。」など、内容に合った形で締める

## キャッチコピーの生成ルール

- **20文字以内**（日本語）を目安にする
- タイトルの `| ` 以降に入る形式（例: `メガロマリア ルビーアイ 筆塗り塗装 | ほんのり赤みがかった白を目指して`）
- 記事のメインテーマ・こだわりポイント・制作意図を一言で表す
- 複数候補（3〜4案）を提示する

## この記事の要約テーブルの生成ルール

- 本文中の `## この記事の要約` 見出し直下に配置する（見出しがなければ導入文とギャラリーの後、`## 序文` の前に新設する）
- 以下の項目を持つMarkdownテーブルにする（記事の内容によって項目の過不足があってもよい）

| 項目             | 内容                                                         |
| ---------------- | ------------------------------------------------------------ |
| 使用キット       | 製品名（ミキシングなど特記事項があれば併記）                 |
| 塗装方法         | 筆塗り／エアブラシなど                                       |
| 主に使った塗料   | ファレホなど、記事内で言及された塗料                         |
| 今回試したこと   | この記事で挑戦した技法・工夫                                 |
| 難しかったところ | 本文中で「難しい」「苦手」「惜しい」などと言及されている工程 |
| 完成後の印象     | 本文の「完成」セクションでの感想・満足度                     |

- 各セルは本文中の記述をもとに要約し、本文にない情報を創作しない
- 既にテーブルが存在する場合は内容を最新化する

## 出力

1. 生成したdescriptionとその文字数を表示する
2. キャッチコピーの候補を複数表示する
3. 生成した「この記事の要約」テーブルを表示する
4. ユーザーに確認を取る（description・キャッチコピー・要約テーブルそれぞれ）
5. 承認されたら、フロントマターの `description` フィールド、`title` フィールドのキャッチコピー部分、本文の「この記事の要約」テーブルを更新する
